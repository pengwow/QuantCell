# Troubleshooting

## Installation

### `uv sync` fails or dependency conflicts

- Confirm Python 3.14 (the project's target version): `python3 --version`
- Clean the cache and reinstall: `uv cache clean && uv sync`
- The trading kernel is a full maturin path dependency — the first sync needs a Rust
  toolchain and can take a while; this is normal

### `quantcell` command not found

`quantcell` is generated by `uv sync` under `backend/.venv/bin/`:

```bash
export PATH="$PATH:$(pwd)/backend/.venv/bin"   # or use the full path
backend/.venv/bin/quantcell --help
```

### Frontend fails to start

- Make sure you use bun, not npm: `bun install && bun run dev`
- If the dependency cache is broken, delete `frontend/node_modules` and
  reinstall

## Runtime

### Backend starts but the page won't open

- Frontend dev mode and the backend use separate ports: backend `8000`,
  frontend `5173` (vite default)
- Make sure you open the vite dev URL, not 8000 (8000 only serves the API
  and Swagger)

### `/metrics` returns 404

The Prometheus metrics endpoint is gated by a **capability flag**: query
`/api/v1/extensions` and enable the corresponding capability.

### Port conflicts

Before `make dev-start`, run `make dev-status` / `make dev-stop` to clean up
leftover processes.

## Data

### Backtest reports "data missing"

```bash
quantcell data download -s BTCUSDT -i 1h
quantcell data quality check --start <start> --end <end>
```

Let it backfill missing gaps automatically, then retry.

### Timestamps look wrong

The system uses nanosecond precision throughout; convert hand-written data
sources first (milliseconds × 1_000_000).

## Backtesting

### Backtest results differ from the Python path

- Confirm you haven't mixed the `fundingRate` data type with the
  `funding_by_symbol` settlement channel (double billing)
- `bookDepth` / `bookTicker` are mid-price synthetic quotes — no real
  matching occurs
- Multi-symbol runs use a "per-symbol independent cash pool" basis — don't
  interpret them as a single pooled account

### Engine behaves unexpectedly

The Rust engine .so may be stale (kernel sources changed without reinstalling;
the package name is the path dependency in `backend/pyproject.toml`):

```bash
cd backend && uv sync --frozen --reinstall-package <engine-package>
uv run pytest tests/conformance/ -q     # the conformance gate flags this first
```

## Live trading

### API key validation fails

- Re-enter credentials with `quantcell account add`; verify the exchange and
  key match with `quantcell account list`
- Check exchange-side IP allowlists and permissions (trading on,
  withdrawals off)

### paper vs live behavior differences

- paper matching has no real slippage or queue position — worse fills on
  live are normal
- Confirm the risk engine configuration is identical in both modes

### LLM strategy backtest raises ReplayMissError

Backtests only replay recorded decisions — **no real LLM requests**:

- Run the strategy on paper / live for a while to accumulate recordings
  (`backend/data/llm_replay`)
- Or point the strategy parameter `llm_replay_path` at an existing recording
  directory

## Desktop client

### macOS "cannot verify developer"

System Settings → Privacy & Security → Open Anyway; or right-click → Open.

### sidecar backend doesn't start

- Check the Tauri logs to confirm the `quantcell-backend` binary exists and
  is executable
- The first run may be blocked by Gatekeeper — allow it and retry
